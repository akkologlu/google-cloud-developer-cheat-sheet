# Style Guide

This document defines the writing style used throughout the handbook.

---

# Tone

Professional.

Friendly.

Developer-oriented.

Avoid corporate marketing language.

---

# Voice

Explain concepts like a senior engineer mentoring another engineer.

Avoid unnecessary complexity.

---

# Paragraph Length

Keep paragraphs short.

3–6 lines whenever possible.

---

# Lists

Prefer bullet lists.

Avoid walls of text.

---

# Tables

Use tables for comparisons.

Example:

| Cloud Run  | GKE        |
| ---------- | ---------- |
| Serverless | Kubernetes |

---

# Terminology

Always use official Google Cloud terminology.

Examples:

- Compute Engine
- Virtual Machine (VM)
- Cloud Run
- Artifact Registry

Do not invent new names.

---

# Language of Technical Terms

In Turkish (`.tr.md`) content, keep Google Cloud service names, product names, and technical terms in their original English form. Do not translate them into Turkish.

Examples:

- "Service Account" — not "Hizmet Hesabı"
- "Load Balancing" — not "Yük Dengeleme"
- "Preemptible VM" — not "Kesilebilir VM"

Only the surrounding prose is written in Turkish; the terms themselves stay in English, exactly as they appear in the English content and in official Google Cloud documentation.

---

# Definitions

Every definition should answer:

What?

Why?

How?

---

# Analogies

Every important service should have at least one analogy.

Examples:

VPC → City

Subnet → Neighborhood

Firewall → Security Gate

Docker Image → Recipe

Container → Meal

Deployment → Restaurant Manager

Service → Phone Number

---

# Diagrams

Prefer Mermaid diagrams over images.

Keep diagrams simple.

---

# Emojis

Use emojis only in headings.

Never inside paragraphs.

---

# Markdown

Always use GitHub-compatible Markdown.

Avoid HTML.

Use relative links.

---

# Examples

Every chapter should contain at least one real-world example.
